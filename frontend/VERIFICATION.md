## 浏览器验收

从仓库根目录启动独立验收实例：

```sh
python frontend/tests/serve-visitor.py --port 8765
```

该脚本复用已有 FastAPI 和生产前端，数据库位于系统临时目录，使用项目自带的 DSH_FORCE_MOCK 模式，不调用付费模型。仅在验收进程中替换模型可用性探测，并为流水线增加短暂等待，以便验证运行中的刷新；后端文件不作修改。退出进程后清理临时目录。

在全新浏览器会话访问 http://127.0.0.1:8765，桌面视口 1440 × 1080，已验证：

1. 初次打开无需管理密钥；高级选项默认折叠，未输入正文时不能提交。
2. 上传合成 TXT 合同可看到正文；切换历史再返回，草稿仍在。
3. 提交后显示运行进度；重复提交、切换审查模式、加载示例和替换文件均被禁用。
4. 审查中刷新，恢复同一个任务，完成后自动打开报告。
5. 报告显示对应风险；等级筛选生效；原文、法条和建议可展开；访客不显示人工裁决按钮。
6. Word 和 JSON 导出在浏览器实际完成。检查 JSON 风险数量与页面一致，检查 DOCX 是有效 ZIP/Word 文档且包含合成风险原文。
7. 完成后刷新页面，从历史记录重新打开原报告；记录数量、完成状态和风险数量正确。
8. 桌面报告没有横向页面溢出，浏览器没有应用脚本错误。
9. 示例报告可打开，原有法条依据、替代条款与复制入口保留。

Windows 下 agent-browser 的 download 命令在本机测试中报告取消。使用该测试浏览器的 CDP 下载配置，将文件保存到系统临时目录，再点击页面原有导出按钮，成功获得 JSON（29,581 字节）及 Word（38,551 字节）。导出逻辑没有因此改动。

验收只确认前端行为与现有接口衔接，不代表真实模型质量或线上部署已验证。截图和合成合同保存在被 Git 忽略的 frontend/.tmp/visitor-ui，导出文件保存在系统临时目录，均不提交。
