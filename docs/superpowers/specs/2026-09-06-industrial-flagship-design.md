# 工业级旗舰合同审查助手设计

## 目标

把一次性合同审查 demo 升级为可部署、可审计、可评测、可演进的内部法务平台。系统默认单租户本地运行；通过稳定的存储与身份接口支持 PostgreSQL、对象存储和企业 SSO 的后续替换。

## 架构

请求先被认证和授权边界包裹，再进入 Review Run。推理产生的报告固定为不可变快照；人工裁决、反馈、评测和追踪作为追加事实保存，读取时投影到报告。法规语料、检索和重排暴露独立接口，避免让 LangGraph 节点依赖具体数据库或向量库。

## 组件

- `ReviewRunStore`：审查生命周期、事件、人工裁决、可恢复执行。
- `TenantStore`：用户、租户、角色和 API-key 认证；无认证模式仅限开发环境。
- `AuditStore`：追加式审计日志，记录谁在何时对哪个租户的数据做了什么。
- `TraceStore`：记录流水线阶段的延迟、模型、输入输出 token 与错误；提供聚合运行指标。
- `FeedbackStore`：记录人工裁决与自由反馈，导出不含合同原文的评测样本。
- `LegalRetriever`：法规版本过滤、关键词/词项混合召回、确定性重排与可解释命中来源。
- `EvaluationGate`：基于基准集阈值比较当前结果与基线，作为 CI 发布门禁。

## 安全与部署

运行时数据库、密钥和上传原件均不进入 Git。生产配置强制设置认证密钥、禁用开发绕过，并用 Docker 非 root 用户启动。CI 执行测试、前端构建、报告结构检查和评测门禁。云端密钥、对象存储与 TLS 由环境变量接入，不在仓库保存凭据。

## 验收标准

- 非开发环境的所有业务端点必须带有效身份；角色和租户不匹配返回 403/404。
- 审查、裁决、反馈和失败均产生日志与 trace，且可按租户查询。
- 法规检索的证据明确含语料版本、命中分与来源；报告保存对应快照。
- 评测门禁能阻止低于阈值的指标结果。
- `pytest tests/ -q` 和 `npm run build` 可通过；镜像可由 Docker Compose 启动。
