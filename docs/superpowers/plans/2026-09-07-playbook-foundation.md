# Playbook 基础与审查快照实施计划

**Goal:** 完成一期首个切片：Playbook 领域模型、版本化存储和审查运行快照绑定。

**Architecture:** 沿用 SQLite adapter。Playbook 内容与版本生命周期分离，发布时冻结完整内容和 SHA-256；审查入队前复制已发布快照，执行、报告和历史读取均使用该副本。

**Tech Stack:** Python 3.11+、Pydantic 2、SQLite、FastAPI、pytest；不增加依赖。

**Spec:** `docs/UPGRADE_ROADMAP.md` 一期 Playbook 要求；本次不涵盖工作台 UI、证据卡片扩展、红线包与版本差异。

## 约束与决策

- 用户已授权依路线图直接实施；在当前干净工作区交付可审查改动。
- 测试先失败再实现。测试数据库、配置放临时目录；强制 mock，不调用真实模型。
- 不提交 `.env`、`settings.json`、密钥、数据库或合同原文。
- 版本状态为 `draft`、`active`、`archived`；只有草稿可更新。归档改变生命周期，不改变已发布快照；新修订分配新版本号。
- 内容含名称、合同类型、法域、业务场景、生效范围和规则。规则包含风险类型、严重度、触发条件、审查问题、可接受条件、替代条款、升级策略及可选 worker 类目。
- 所有 Playbook 读写按租户过滤，变更保留操作者和时间；发布与版本号分配使用事务。
- 上传可以指定 `playbook_id` / `playbook_version`。旧客户端不传时绑定现有风险矩阵的内置基线快照；旧数据库已有运行保持未绑定，不伪造历史依据。
- 自定义 Playbook 校验合同类型、法域、业务场景、生效范围。快照在创建运行时保存，不在排队结束后重新解析最新版本。
