# 一期与二期剩余能力实施计划

**Goal:** 补齐一期审查交付验收项和二期本地能力，并提供不泄露合同数据的外部平台适配器与契约测试。

**Architecture:** Playbook 规则以已冻结快照作为审查输入并产出独立来源的规则发现；报告规范统一证据、置信度和人工处置，DOCX 输出可交付审查包；资产修订链保存原稿/修订稿和风险影响。SLA 使用工作日历和幂等升级提醒，外部系统通过显式配置、签名、超时和出站白名单适配器发送事件。

**Tech Stack:** Python/Pydantic/SQLite/FastAPI/python-docx、Vue、pytest/node:test。

**Spec:** docs/UPGRADE_ROADMAP.md 一期未完成项、二期未完成项；用户授权一次完成仓库内能力，真实外部联调待平台配置。

## 全局约束

- 测试优先：每个高风险模块至少观察关键失败测试；主体实现后统一全量测试。
- 不提交密钥、运行数据库、合同原文、构建产物、OCR/向量模型。
- 模型判断、Playbook 规则、法条来源和人工决定必须在输出中可区分。
- 冻结快照和历史版本不可被后续编辑改写；所有租户与资产读取权限贯穿新端点。
- 外部适配器默认关闭，只允许明确配置的 HTTPS 目标，不记录请求正文或密钥，不声称真实平台已联调。
