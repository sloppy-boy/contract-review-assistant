# 合同审查助手旗舰升级路线图

> 本文是切换会话/模型后的工作入口。当前分支的已完成基础、一期交付边界、后续演进顺序和验收口径均以本文为准。

## 当前基线（备份点前）

项目已经具备以下能力：

- LangGraph 多阶段合同审查：提取、并行审查、对抗复核、结构化报告。
- 多供应商模型配置与角色路由；线上审查运行可持久化、恢复、展示阶段耗时。
- 法条手册版本与快照、基础检索、人工接受/驳回风险项、审查历史。
- Word 审阅报告导出、Docker Compose、前端生产构建和后端自动化测试。
- 身份、审计、反馈、观测和评测门禁的基础模块。

已知限制：当前 Word 导出仍是“审阅报告”，并非原合同的修订痕迹；检索器尚未达到可量化验证的稠密召回 + 关键词召回 + 重排能力；部分企业治理模块尚未贯穿全部读取端点。不要把这些基础模块表述为已完成的企业级合规能力。

## 产品定位

**面向中国企业法务的、可证据化、可红线、可治理的合同审查操作系统。**

不在第一阶段复制完整 CLM。优先做出一条法务人员能够在真实审查中交付和留痕的闭环：

```text
选择合同类型 → 选定版本化 Playbook → 证据化审查
→ 风险逐项处置 → 导出红线审查包 → 留存可追溯快照
```

## 一期：审查交付旗舰版

### 目标

让每一条风险都能回答五个问题：审查依据什么标准、合同哪里有问题、建议如何改、法务最终如何处置、交付物如何被业务/对方使用。

### 范围

1. **Playbook 工作台**
   - 按合同类型、法域和业务场景组织审查标准。
   - 规则包含：风险类型、严重度、触发条件、审查问题、可接受条件、推荐替代条款、升级策略。
   - Playbook 必须有版本、状态（草稿/生效/归档）、生效范围、创建与发布记录。
   - 审查运行固定记录所用 Playbook 及其版本快照；历史结果不得被之后的规则修改改写。

2. **证据化风险卡片**
   - 每项风险统一展示：合同定位、原文摘录、风险说明、合同事实/数值证据、法规或 Playbook 依据、替换建议、置信度、人工升级建议。
   - 对缺少足够证据或低置信度的项目，明确标为“需人工确认”，不得伪装成确定结论。
   - 保持现有人工接受/驳回机制，新增“待确认”和“采用替代条款”等可审计处置状态及处置理由。

3. **红线审查包（DOCX）**
   - 一期不修改原始 DOCX 的 Word Track Changes XML。
   - 导出正式审查包：合同摘要、使用的 Playbook、风险清单、原文、建议替换文本、依据、处置结果和审查时间线。
   - 对含有原文定位的风险，使用稳定的条款/段落编号；复制建议替换文本可直接发送至谈判方或贴入 Word。

4. **版本差异的最小闭环**
   - 同一审查事项可关联“原稿/修订稿”两个文本版本。
   - 展示文本级/条款级变更、受影响的风险项和处置是否仍有效。
   - 一期仅支持文本和结构化段落的差异，不承诺保留复杂 DOCX 格式。

### 非目标

- 不在一期建设 Office Word 加载项。
- 不承诺原始 DOCX 修订痕迹写入或复杂版式无损编辑。
- 不建设全量合同库、电子签约、续签日历、企业 SSO/SCIM；这些属于后二、三期。

### 一期验收标准

- 可创建、发布、归档 Playbook；生效版本不可变。
- 任何审查运行能追溯到 Playbook 版本、风险证据和人工处置事件。
- 风险缺证据或低置信度时自动提示人工确认。
- 红线审查包包含原文/建议/依据/处置，不改变已有报告下载能力。
- 上传两个关联文本后，系统能指出变更段落与受影响风险。
- 新增功能均有先失败、后通过的自动化测试；现有 `pytest tests/ -q` 和 `npm run build` 不回归。

### 推荐实现顺序

1. 设计 Playbook 领域模型、存储和不可变版本快照。
2. 将审查运行绑定到 Playbook；扩展风险卡片的证据、置信度和处置状态。
3. 增强审查包 DOCX 导出与前端风险处置体验。
4. 新增同事项双版本文本差异与风险影响投影。

## 二期：法务协作与合同资产

1. 审查发起单、指派、SLA、审批关卡、评论/@提及和通知。
2. DOCX/PDF/OCR 导入、批量导入、合同元数据提取。
3. 合同仓库、标签、权限、全文/语义检索和跨合同问答。
4. 义务、续签和关键日期提醒；对接企业 IM、工单、采购/CRM 与电子签约。

**验收信号：** 一个法务团队可从收件、审查、谈判、批准到履约提醒均在系统中留痕完成。

## 三期：企业级治理与规模化运行

1. PostgreSQL、对象存储、队列、取消/重试/死信与供应商降级。
2. OIDC/SAML SSO、SCIM、细粒度 RBAC/ABAC、完整租户隔离。
3. 加密、密钥托管、PII 脱敏、保留/删除/法务保全、导出控制与可检索审计。
4. 链路追踪、成本归因、告警、SLO；模型/Playbook 维度的离线评测、发布门禁和线上抽检。
5. 检索升级为稠密召回 + 关键词召回 + rerank，并持续度量 Recall@K、引用正确率和风险漏检率。

**验收信号：** 可通过企业安全评审，并在多用户、多合同、高并发和模型供应商故障下可观测、可恢复地运行。

## 工作约束

- 不提交 `.env`、`settings.json`、模型密钥、运行数据库或合同原文。
- 所有审查结论必须区分模型判断、Playbook 规则、法条/来源和人工决定。
- 新功能使用测试优先；先验证失败，再以最小实现通过。
- 真实生产部署前，安全、法务规则有效性和模型输出必须由相应负责人复核。
